# M1.9.1 추천 UI 분리 및 API 계약 초안

## 이번 단계 목적

엔진 로직과 추천 UI를 분리해 iOS 코드 구조를 정리하고, 이후 NestJS 서버로 계산/교정 엔진을 이관할 때 사용할 API 계약 초안을 고정합니다.

이번 반영은 **동작 변경보다 구조 정리**가 목적입니다.

## 반영 내용

### 1. 추천 UI 파일 분리

기존 `HanwooPrototypeApp.swift`에 함께 있던 추천 화면 관련 뷰를 별도 파일로 이동했습니다.

분리 대상:

- `AIRecommendationView`
- `RecommendationCard`

신규 파일:

- `/apps/ios/HanwooPrototype/HanwooPrototype/RecommendationViews.swift`

유지 대상:

- `StatusPill`
- `ComparisonRow`
- `BulletLine`
- `correctionActionLabel`

이들은 아직 분석 화면에서도 함께 쓰이므로 공용 UI/유틸로 유지했습니다.

### 2. 서버 이전용 API 계약 초안

로컬 엔진의 입력/출력을 서버형 구조로 옮길 수 있게 JSON 계약을 먼저 고정합니다.

#### 추천 요청

추천은 분석 응답을 다시 계산하지 않고, 같은 배합 입력을 기반으로 서버에서 생성합니다.

```json
{
  "formulaName": "비육전기 배합안 A",
  "stage": "fatteningEarly",
  "items": [
    {
      "ingredientId": "riceBran",
      "amountKg": 300,
      "unitPriceKrwPerKg": 350
    }
  ]
}
```

## 설계 원칙

- 앱은 `원물 기준 kg`만 전송
- 서버는 `DM 기준 계산` 수행
- 추천안은 `원료 추천`이 아니라 `복합 교정안` 자체를 반환
- AI는 추천안을 계산하지 않고, 서버가 만든 교정안을 설명만 담당
