# M1.9 패턴형 복합 교정 엔진

## 이번 단계 목적

M1.8까지의 교정 엔진은 `순차 단건 교정` 방식이었습니다.

- 과잉 하나 선택 → 원료 1개 감량 → 재계산
- 부족 하나 선택 → 원료 1개 추가/증량

이번 반영부터는 **문제 패턴을 먼저 분류하고, 패턴에 맞는 감량 + 증량 + 보완을 묶은 다중 액션 교정 플랜**을 생성합니다.

예:

```
미강 -15kg
옥수수 +8kg
볏짚 +3kg
```

## 반영 내용

### 1. 문제 패턴 분류

`classifyPattern` 함수가 현재 배합의 영양소 상태를 보고 대표 패턴을 하나 분류합니다.

지원 패턴:

| 패턴 | 설명 |
|---|---|
| `cpAndTdnExcess` | CP과잉 + TDN과잉 |
| `cpExcess` | CP과잉 단독 |
| `tdnExcess` | TDN과잉 단독 |
| `eeExcess` | EE과잉 단독 |
| `eeExcessWithCpDeficit` | EE과잉 + CP부족 |
| `ndfExcess` | NDF과잉 단독 |
| `ndfExcessWithTdnDeficit` | NDF과잉 + TDN부족 |
| `adfExcess` | ADF과잉 단독 |
| `cpAndTdnDeficit` | CP+TDN 동시 부족 |
| `cpDeficit` | CP부족 단독 |
| `tdnDeficit` | TDN부족 단독 |
| `fiberDeficit` | NDF/ADF 부족 (조사료 부족) |
| `complex` | 복합 문제 (순차 교정 fallback) |
| `maintenance` | 모든 기준 충족 |

유의미한 이탈 기준: `0.2%p`. 미만이면 maintenance 또는 complex로 처리합니다.

### 2. 패턴별 교정 템플릿

각 패턴에 액션 묶음 틀을 정의합니다.

**CP+TDN 과잉:**
- CP 기여 원료 감량 + TDN 기여 원료 감량 (2×2 조합)
- 감량 후 NDF가 부족해지면 조사료 보완 추가

**EE과잉 + CP부족:**
- 고지방 원료 감량 + 단백질원 보완 (감량 후 CP 부족분 역산)

**NDF과잉 + TDN부족:**
- NDF 기여 원료 감량 + 에너지 농후사료 증량 (감량 후 TDN 부족분 역산)

**CP+TDN 동시 부족:**
- 단백질원 + 에너지원 동시 보완 (2×2 조합)
- 단독 보완도 후보로 포함

**단일 과잉 (CP/TDN/EE/NDF/ADF):**
- 상위 기여 원료 3순위까지 감량 후보 생성
- 감량 후 CP/TDN 부족이 생기면 보완 액션 자동 추가

**단일 부족 (CP/TDN):**
- 보완 후보 상위 4개 원료에서 플랜 생성

**NDF/ADF 부족 (조사료 부족):**
- 조사료 카테고리 상위 3개 원료에서 보완 플랜 생성

### 3. 액션 묶음 시뮬레이션

각 교정 플랜의 액션 묶음을 `simulateApplying`으로 한 번에 시뮬레이션합니다.

검증 항목:
- CP, TDN, EE, NDF, ADF, Ca, P, Ca:P, 수분

### 4. 플랜 후보 필터링 및 선정

생성된 플랜들은:
1. **중복 제거** (동일 액션 묶음)
2. **하드 제약 검증** (`isPlanViable`): 수분 상한 초과, Ca:P 비율 붕괴 시 제외
3. **3개 전략 슬롯으로 선정**:

| 전략 | 선정 기준 |
|---|---|
| `ownedFirst` | 기존 보유 원료만 사용하는 플랜 중 resolutionRate 최고 |
| `costEffective` | resolutionRate ≥ 30% 플랜 중 costDelta 최소 |
| `balanced` | 전체 플랜 중 resolutionRate 최고 (동률이면 costDelta 낮은 것) |

동일 플랜이 여러 전략에서 선택되면 하나만 노출됩니다.

### 5. UI 구조 유지

`Recommendation` 구조체가 동일하므로 UI는 변경 없습니다.

차이:
- `action` 필드에 다중 액션이 쉼표로 표시됩니다. 예: `미강 -약 15kg, 볏짚 +약 3kg`
- `correctionActions` 배열에 전체 액션 묶음 포함

### 6. 교정 설명문

`buildPatternReason`이 패턴 기반 설명을 생성합니다.

예:
```
현재 배합은 CP+TDN 과잉 패턴입니다.
단백질원 감량 + 에너지원 감량을(를) 적용합니다.
교정 후 비육전기 핵심 기준을 모두 만족합니다.
```

## 확인 포인트

- `CP+TDN 과잉` 배합에서 다중 감량 액션이 묶여 나오는지
- `EE과잉+CP부족` 패턴에서 감량 후 단백질 보완이 동반되는지
- `CP+TDN 부족` 패턴에서 단백질원+에너지원 동시 보완안이 나오는지
- ownedFirst / costEffective / balanced 3개 전략이 서로 다른 플랜으로 노출되는지
- 동일 플랜이 중복 노출되지 않는지
- 감량 후 Ca:P 붕괴 플랜이 자동 제외되는지
