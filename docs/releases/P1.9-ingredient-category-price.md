# P1.9 원료 카테고리 선택 + 가격 조정 릴리즈 노트

## 1. 이번 단계 이름

- `P1.9 원료 카테고리 선택 + 가격 조정`

## 2. 이번 단계 목적

- 원료 선택 구조를 분류 탐색형으로 전환해 실제 농가 사용 흐름에 맞춘다.
- 원료별 kg당 단가를 입력하면 총 원료비가 자동 계산되어 배합 현실성을 높인다.
- 영양성분은 DB 고정값을 사용하고, 사용자는 투입량(kg)과 단가만 조정한다.

## 3. 포함 기능 목록

### 데이터 모델
- `IngredientCategory` enum: 농후사료 / 조사료 / 농산부산물 / 보충사료
- `IngredientDefinition` struct: id, name, category, defaultPriceKrwPerKg, nutrition
- `IngredientLine`에 `definitionID: String?`, `priceOverrideKrwPerKg: Int?` 추가
- 원료 mock DB 12종 (임시값, 추후 축산과학원 공식 성분표로 교체 예정)

### 원료 선택 UI
- `IngredientPickerSheet` → 카테고리 목록 (각 카테고리 종수 표시)
- `IngredientCategoryListView`: 카테고리별 원료 목록, 원료명 + 기본단가 + 주요 영양소 뱃지(수분/CP/TDN/NDF)
- `CustomIngredientInputView`: 직접 입력 원료 추가 (영양소 계산 제외 안내 포함)
- `NutrientBadge`: 원료 목록의 소형 영양소 표시 컴포넌트

### 배합 입력 UI
- `IngredientAmountEditor`에 kg당 단가 입력 필드 + 소계(원) 자동 표시
- 단가 미입력 시 DB 기본단가 적용 안내 표시
- `BlendView` 하단에 총 원료비(원물 기준) 표시

### 계산 로직
- `calculateMetrics`: `definitionID` 기반으로 영양성분 조회 (구 name 기반 map 제거)
- `effectivePricePerKg(for:)`: priceOverride 우선, 없으면 definition 기본값
- `totalCostKrw(for:)`: 배합 내 모든 원료의 원물량 × 단가 합산

## 4. 제외 기능 목록

- 수분 조정 (영양소는 DB 고정)
- 원료별 최소/최대 사용량 제한 (P1.10)
- 가격 기반 최적화

## 5. 우선 확인할 포인트

- 카테고리 탐색 → 원료 선택 → 배합에 추가되는 흐름이 자연스러운지
- 단가 입력 후 소계와 총 원료비가 즉시 반영되는지
- 직접 입력 원료가 영양소 계산에서 제외되고 이유가 명확히 안내되는지
