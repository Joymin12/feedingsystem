# M1.3 과잉 성분 교정 엔진 범용화 릴리즈 노트

## 단계 이름
`M1.3 과잉 성분 교정 엔진 범용화`

## 목적
M1.2에서 조지방(EE) 전용으로 구현된 과잉 교정 엔진을 **NDF/ADF까지 동일한 패턴으로 확장**합니다.
`EECorrectionContext` + `buildEeCorrectionContext`를 범용 구조로 교체하고, 현재 릴리즈 범위에서는 `EE/NDF/ADF` 3개 과잉 성분을 하나의 선택기에서 처리하도록 정리합니다.

---

## 변경 내용

### 1. `EECorrectionContext` → `OverageCorrectionContext` (구조체 교체)
- 기존: EE 전용 필드 구성
- 변경: `nutrientName: String` 필드 추가 (예: `"조지방(EE)"`, `"NDF"`, `"ADF"`)
- 나머지 필드(`reductionAction`, `reducedFormula`, `reducedMetrics`, `reducedCostDeltaKrw`, `targetIngredientName`) 유지

### 2. `buildEeCorrectionContext` → `buildOverageCorrectionContext` (범용 함수)
- 기존: EE 수치만 비교하도록 하드코딩
- 변경: 아래 파라미터로 영양소를 주입받는 범용 함수
  ```swift
  private func buildOverageCorrectionContext(
      formula: FeedFormula,
      stage: FarmStage,
      metrics: AnalysisSummaryMetrics,
      nutrientName: String,
      currentPctDm: Double,
      maxPctDm: Double,
      nutritionPath: KeyPath<IngredientNutritionProfile, Double>,
      metricsPath: KeyPath<AnalysisSummaryMetrics, Double>
  ) -> OverageCorrectionContext?
  ```
- `nutritionPath`: 원료 기여도 계산 시 사용하는 KeyPath (예: `\.eePctDm`, `\.ndfPctDm`)
- `metricsPath`: 이진 탐색 종료 조건 판단 시 사용하는 KeyPath (예: `\.eePctDm`, `\.ndfPctDm`)
- 이진 탐색 14회 로직, 기여도 1위 원료 선정 로직은 M1.2와 동일

### 3. `buildMostSevereOverageContext` 추가 (최우선 과잉 선택)
- EE / NDF / ADF 세 영양소의 기준 초과폭(`currentPctDm - maxPctDm`)을 비교
- 초과폭이 가장 큰 영양소 하나를 선택해 `buildOverageCorrectionContext` 호출
- 초과 영양소가 없으면 `nil` 반환
- `buildRecommendations`는 이 함수 하나만 호출하면 됨 (EE/NDF/ADF 분기 불필요)
- 새 과잉 성분을 추가할 때는 `buildMostSevereOverageContext`의 선택 대상 목록에 해당 성분을 명시적으로 추가해야 함

### 4. `buildRecommendations` 호출부 변경
- `buildEeCorrectionContext(...)` → `buildMostSevereOverageContext(...)`
- `eeContext` 변수명 → `overageContext`
- 3개 전략(보유원료/가성비/균형) 모두 `overageContext`를 전달

### 5. `makeRecommendation` 파라미터 및 내부 텍스트 동적화
- 파라미터명: `eeContext: EECorrectionContext?` → `overageContext: OverageCorrectionContext?`
- 교정 이유 문구: `"조지방 과다를 완화하기 위해..."` → `"\(overageContext.nutrientName) 과다를 완화하기 위해..."`
- 장점 문구: `"조지방 과다 완화"` → `"\(overageContext.nutrientName) 과다 완화"`

### 6. `eeOnlyRecommendation` → `overageOnlyRecommendation` (단독 교정안 동적화)
- 제목: `"조지방 교정안"` → `"\(context.nutrientName) 교정안"`
- 이유 문구: `"조지방(EE)이 기준선을 넘어..."` → `"\(context.nutrientName)이 기준선을 넘어..."`
- 권장량 주석: `"조지방 기준 교정량"` → `"\(context.nutrientName) 기준 교정량"`
- 장점: `"조지방 과다 완화"` → `"\(context.nutrientName) 과다 완화"`

---

## 제외 기능
- 다중 과잉 성분 동시 교정 (EE + NDF 동시 초과 시 가장 심각한 것 하나만 처리)
- Ca:P 과잉 교정 (Ca:P는 범위 지표이나 교정 패턴이 단순 감량과 다름 — 별도 검토 필요)
- 과잉 원인 원료가 배합 내 없거나 양이 0.1kg 미만인 경우 — nil 반환으로 처리 유지
- 새로운 과잉 성분 자동 등록 구조 (현재는 `EE/NDF/ADF` 3개를 명시적으로 선택)

---

## 확인 포인트
- NDF가 기준 초과인 배합에서 NDF 기여도 1위 원료 감량 액션이 생성되는지
- ADF가 기준 초과인 배합에서 ADF 기여도 1위 원료 감량 액션이 생성되는지
- EE/NDF/ADF 동시 초과 시 초과폭이 가장 큰 영양소 하나만 선택되는지
- 교정안 제목·이유·권장량 주석에 해당 영양소명이 올바르게 표시되는지
- EE만 초과인 M1.2 케이스가 기존과 동일하게 동작하는지 (회귀 없음)
