# M1.4 엔진 파일 분리 릴리즈 노트

## 단계 이름
`M1.4 엔진 파일 분리`

## 목적
2600줄이 넘던 `HanwooPrototypeApp.swift` 단일 파일을 역할별로 분리합니다.
계산 엔진과 교정 엔진을 별도 파일로 옮겨 코드 가독성과 유지보수성을 높입니다.
또한 새 파일 2개를 Xcode 타깃에 포함시켜, 분리 후에도 기존 분석/추천 흐름이 동일하게 빌드되도록 정리합니다.

---

## 파일 구조 변경

| 파일 | 줄 수 | 역할 |
|---|---|---|
| `HanwooPrototypeApp.swift` | ~2058줄 | 데이터 모델, PrototypeStore(상태·CRUD), 유틸리티 함수, 전체 View |
| `PrototypeStore+CalculationEngine.swift` | ~212줄 | 계산 엔진 |
| `PrototypeStore+CorrectionEngine.swift` | ~706줄 | 교정 엔진 |

---

## 이동된 코드

### `PrototypeStore+CalculationEngine.swift` (신규)
`extension PrototypeStore`로 구성. 계산 및 시뮬레이션 전용:
- `calculateMetrics(for:)` — 배합 → 영양소 수치 계산 (DM 기준)
- `simulateAdding(ingredientID:amountKg:to:)` — 원료 추가 시뮬레이션
- `simulateApplying(actions:to:)` — 복수 CorrectionAction 적용 시뮬레이션
- `buildSummary(stage:metrics:missingIngredients:totalIngredients:)` — 분석 요약 문구
- `buildStatuses(stage:criteria:metrics:)` — 영양소별 상태 카드 목록

### `PrototypeStore+CorrectionEngine.swift` (신규)
`extension PrototypeStore`로 구성. 교정·추천 전용:
- `private struct RecommendationCandidate` — 후보 원료 평가 구조체 (파일 내부 전용)
- `private struct OverageCorrectionContext` — 과잉 교정 컨텍스트 구조체 (파일 내부 전용)
- `buildOverageCorrectionContext(...)` — 과잉 성분 교정 컨텍스트 생성 (범용)
- `buildMostSevereOverageContext(...)` — EE/NDF/ADF 중 최우선 과잉 선택
- `buildRecommendations(...)` — 3전략 추천안 생성
- `buildRecommendationCandidates(...)` — 후보 원료 시뮬레이션 및 평가
- `makeRecommendation(...)` — 추천안 조립
- `overageOnlyRecommendation/maintenanceRecommendation/noSolutionRecommendation` — 케이스별 추천안
- 정렬 비교자: `ownedFirstComparator`, `costEffectiveComparator`, `balancedComparator`
- 문구 생성: `strategyReason`, `recommendationFocus`, `buildReason`, `buildPros`, `buildCons`, `primaryCaution`
- 권장량 계산: `suggestedAmountGuide`, `recommendedAmountRange`, `largerAmountRange`, `upperBoundKg`, `median`
- 내부 헬퍼: `allCoreTargetsSatisfied`, `cpDeficit`, `tdnDeficit`, `trialAmount`, `effectivePricePerKgInFormula`

## 접근 수준 변경

### 유틸리티 함수 (`private` → `internal`)
`HanwooPrototypeApp.swift` 하단의 top-level 유틸리티 함수들에서 `private` 키워드 제거.
extension 파일에서 접근할 수 있어야 하기 때문입니다.
대상: `asFedKg`, `nutrientKg`, `pctDm`, `numberString`, `percentString`, `rangeDistance`, `caPRatioDistance` 등 22개 함수.

### 엔진 함수 (`private func` → `func`)
extension 파일로 이동된 엔진 함수들도 `private` 제거 (같은 이유).
단, extension 파일 내부에서만 쓰이는 `buildRecommendationCandidates`, `makeRecommendation`, 각종 비교자·문구 생성 함수는 `private` 유지.

### 명칭 변경
- `effectivePricePerKg(for:within:)` → `effectivePricePerKgInFormula(for:within:)`
  기존 `effectivePricePerKg(for item: IngredientLine)` 와의 이름 충돌 방지.

## 확인 포인트
- Xcode에서 세 파일 모두 같은 타깃에 포함되어 있는지
- `calculateMetrics`, `buildRecommendations` 등이 `PrototypeStore`의 `analysis(for:)` 에서 정상 호출되는지
- `asFedKg`, `nutrientKg` 등 유틸리티 함수가 extension 파일에서 접근 가능한지
- 빌드 후 기존 동작(배합 분석, 추천안 생성)이 동일하게 유지되는지

## 구현 메모
- 초기 분리 시 `PrototypeStore+CalculationEngine.swift`, `PrototypeStore+CorrectionEngine.swift`가 Xcode 프로젝트 타깃에 누락되어 `cannot find in scope` 빌드 오류가 발생했습니다.
- 이번 릴리즈 기준으로는 두 파일을 `project.pbxproj`의 `PBXFileReference`, `PBXBuildFile`, `PBXSourcesBuildPhase`에 모두 추가해 빌드 복구까지 완료된 상태를 기준으로 합니다.
