# Supabase Auth/Community Setup

Supabase is optional for the current release path. If used later, it should cover only:

- Sign-up / login / logout.
- User profile.
- User-specific ingredient selection.
- Community post create/read/delete.

Formula calculation and the composite correction engine must continue to run locally in the iOS app.

## App Configuration

Add these values to the generated Info.plist build settings for the Xcode target `HanwooPrototype`:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`

If both values are empty, the app stays in local fallback mode. If values are present, the app switches to Supabase mode.

## App Behavior

### Sign-Up

1. User enters email, password, and selected ingredients.
2. App calls Supabase Auth `signUp`.
3. Ingredient IDs are sent as `raw_user_meta_data.selected_ingredient_ids`.
4. If email confirmation is enabled, sign-up completes without a session.
5. User confirms email and logs in.
6. On first login, the app upserts `profiles` and fills `user_ingredients` from metadata if empty.

### Login

1. App calls `auth/v1/token?grant_type=password` with email/password.
2. App stores access token and refresh token.
3. App fetches current user through `auth/v1/user`.
4. App loads `profiles`, `user_ingredients`, and `community_posts`.

### Community

- Read: public.
- Create: authenticated users only.
- Delete: post author or `profiles.is_admin = true`.

## Current Constraints

- In Supabase mode, login input is treated as email.
- The old local admin account `qwer123 / asdf123` is not used in Supabase mode.
- In production, admins should be email-based users with `profiles.is_admin = true`.

## Grant Admin Permission

1. Create a normal account by email sign-up.
2. Run this SQL in Supabase SQL Editor:

```sql
update public.profiles
set is_admin = true
where email = 'admin@example.com';
```
