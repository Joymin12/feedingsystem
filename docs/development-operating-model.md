# 한우 앱 개발 운영안

## 목적

- 개발을 생각나는 대로 진행하지 않고 `단계 -> 우선순위 -> 릴리즈` 단위로 고정한다.
- 각 단계가 끝날 때마다 이번 릴리즈에 포함된 내용과 다음 우선순위를 사용자에게 명확히 전달한다.
- 사용자가 직접 써보고 피드백한 내용을 다음 단계 설계에 반영한다.

## 운영 흐름

`요구 제안 -> 구조화/우선순위화 -> 프로토타입 또는 구현 -> 단계 릴리즈 요약 전달 -> 사용자 사용/피드백 -> 다음 단계 조정`

## 단계 정의

### P0. 화면/흐름 고정

- 목적: 피그마에서 사용자 흐름 확정
- 최상 우선순위: 회원가입, 단계 선택, 홈, 배합, 분석 결과, 최근 분석, 사육일지, 내 농장
- 중간 우선순위: 커뮤니티
- 낮음 우선순위: 세부 장식, 마이크로 인터랙션

### P1. iOS 설치형 프로토타입

- 목적: Xcode로 아이폰에 직접 설치해서 실제 사용
- 최상 우선순위: 로그인/회원가입, 단계 선택, 하단 탭 구조, 배합 입력, 분석 결과, 최근 분석, 사육일지
- 중간 우선순위: 내 농장, 기록 수정 UX
- 낮음 우선순위: 커뮤니티 상세, 설정 세부 옵션

### P2. 사용성 검증 / 요구 재정의

- 목적: 사용자가 직접 써보고 문제를 기준으로 구조 조정
- 최상 우선순위: 입력 불편, 흐름 끊김, 이해 안 되는 결과
- 중간 우선순위: 정보 부족, 문구 수정, 화면 정리
- 낮음 우선순위: 비주얼 고도화

### M1. 실제 기능 구현

- 목적: 검증된 구조를 실제 제품으로 구현
- 최상 우선순위: 농가 정보, 배합 저장, 분석 계산, 최근 분석, 사육일지 저장/수정/조회
- 중간 우선순위: 추천 로직, AI 설명
- 낮음 우선순위: 커뮤니티 고도화, PDF/엑셀 등 부가 기능

### B1. 파일럿

- 목적: 실제 농가 사용 검증
- 최상 우선순위: 실제 사용 가능성, 기록 지속성, 추천 납득성
- 중간 우선순위: 속도, 안정성
- 낮음 우선순위: 확장 기능

## 매 단계 릴리즈 보고 형식

1. 이번 단계 이름
2. 이번 단계 목적
3. 포함 기능 목록
4. 제외 기능 목록
5. 우선 확인할 포인트
6. 다음 단계 후보

## 운영 원칙

- 사용자 역할: 사용자/제품 오너
- 개발자 역할: 구현 + 기술 가이드 + 우선순위 관리
- 기능은 항상 `최상 / 중간 / 낮음` 우선순위로 관리한다.
- 릴리즈는 기능이 모호한 상태에서 하지 않는다.
- 각 단계는 반드시 `이 단계에서 확인할 사용자 행동`을 가진다.

## 현재 기본값

- 개발 모델: 프로토타입 검증 기반 개발
- 플랫폼 우선순위: iOS 먼저
- 첫 실행형 목표: Xcode로 아이폰에 설치 가능한 SwiftUI 프로토타입
- 다음 우선순위 1순위: P1 iOS 설치형 프로토타입
- 첫 P1 릴리즈 범위: 전체 탭형
