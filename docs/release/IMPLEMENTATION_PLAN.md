# Hanufit 출시 구현 계획 (IMPLEMENTATION_PLAN)

## 목표

프로토타입을 출시 가능한 iOS 앱으로 전환한다. 핵심 가치는 하나다:

> 입력된 배합의 영양값을 판정하고, 과잉·부족을 **증감 시뮬레이션**으로 교정해
> 적정 범위에 최대한 가까운 **복합 교정 배합비**를 제시한다.

## 확정된 제품 규칙 (변경 시 승인 필요)

1. 입력은 원물(as-fed) kg, 계산은 건물(DM) 기준.
2. 판정은 성장단계(육성기/비육전기/비육후기) 기준표에 따라 부족/주의/적정/과잉 4단계.
3. 교정 후보는 **배합에 이미 들어 있는 원료만** 사용한다. 부족한 공급원은
   문구로만 제안한다("석회석 같은 칼슘원 추가를 검토해보세요").
4. 최종안은 사용자가 입력한 **총 원물 kg으로 비례 정규화**해 반환한다.
5. 대표 추천안은 **1개**. 완전 적정이 불가능하면 결과를 지어내지 않고
   한계 요인을 명시하고 가장 가까운 참고안을 함께 보여준다.
6. 외부 AI API(OpenAI/Gemini/Claude 등)를 사용하지 않는다. 모든 계산·시뮬레이션은
   로컬에서 결정론적으로 수행한다.
7. 수분 기준: 40~45% 적정, 36~49% 주의, 하드맥스 50%.

## "AI"의 의미와 향후 도입 계획

### 1차 출시 (이번 릴리즈)

- 사용자에게 보이는 "증감 시뮬레이션"은 **로컬 결정론적 최적화 엔진**이다.
  같은 입력이면 항상 같은 결과가 나오고, 모든 수치는 앱의 계산 엔진이 산출한다.
- UI 문구는 "증감 시뮬레이션", "최적화 엔진", "스마트 교정"을 사용한다.
  실제 학습 모델이 없으므로 "AI 모델"이라는 표현으로 포장하지 않는다.
- 사용자 데이터는 기기를 떠나지 않는다.

### 2차 이후: 생성형 AI 설명 계층 (선택 기능)

목적: 엔진이 확정한 결과를 농가 친화적 자연어로 풀어쓰는 것. **후보 생성·수치
계산·판정에는 관여하지 않는다.**

- 경로: 앱 → 자체 백엔드 프록시(NestJS `apps/api` 또는 Supabase Edge Function)
  → LLM API. **API 키를 앱에 내장하지 않는다.**
- 계약: 엔진 산출물(`Recommendation` — 전/후 지표, 판정, 액션, 해결률, 한계
  요인)을 JSON으로 직렬화해 전달. 이 구조는 P2에서
  `RecommendationExplanation`으로 이미 분리해 두므로 백엔드만 추가하면 된다.
- 가드레일(시스템 프롬프트에 고정): 수치 재계산·창작 금지, 판정 번복 금지,
  배합 외 원료 kg 제시 금지, 단정 표현 금지, 5단 구조
  (핵심 문제→1차 조정+이유→교차 영향→2차 보완→기대 결과+주의).
- 실패 시 폴백: 네트워크/서버 불가 시 현재 로컬 설명 문구를 그대로 사용.
  앱은 항상 단독으로 동작한다.
- 온디바이스 대안: Apple Foundation Models(iOS 26+) 검토 가능. 기기 제한과
  한국어 품질 검증 후 결정.

### 로컬 ML 모델 도입 시 (장기)

- `CorrectionEngine`은 `IngredientProviding` 프로토콜과 순수 값 타입만 사용하므로,
  후보 생성부를 Core ML 모델로 교체하더라도 검증(시뮬레이션 재계산)과 정규화
  파이프라인은 그대로 유지한다. 모델이 후보를 제안하고 엔진이 검증하는 구조를
  변경하지 않는다.

## 아키텍처 원칙

- 모듈 경계: 도메인 모델 / 검증 / 계산(평가) / 최적화·시뮬레이션 / 설명 /
  영속화 / 내보내기 / UI. 상세는 ARCHITECTURE.md.
- 기준표·단위·가중치를 UI에 하드코딩하지 않는다. `StageCriteria` 등 도메인
  타입에 정의한다.
- 모든 저장 분석에 `algorithmVersion`을 기록해 엔진이 바뀌어도 과거 결과를
  재현·설명할 수 있게 한다.

## 완료 기준

- 입력→판정→시뮬레이션→추천→저장→내보내기 전체 플로우가 동작한다.
- 외부 AI API 미사용.
- 추천은 재현 가능하고(결정론) 설명 가능하다.
- 불능 케이스는 원인을 설명한다(결과 조작 금지).
- 재설계된 UI가 iPhone/iPad에서 동작한다.
- 핵심 테스트 통과, Release 빌드 재현 가능.
- placeholder 화면·mock 계산 로직 잔존 없음.
