# 최적화 엔진 명세 (OPTIMIZATION_ENGINE)

대상 코드: `apps/ios/HanwooPrototype/HanwooPrototype/CorrectionEngine.swift`,
`CalculationEngine.swift`. 알고리즘 버전은 `CorrectionEngine.algorithmVersion`.

## 1. 계산 기초 (CalculationEngine)

모든 평가는 다음 결정론적 공식으로만 수행한다.

```
DM% = 100 − 수분%
원료 건물 kg   = 원물 kg × DM% / 100
영양소 %DM     = Σ(원료 건물 kg × 원료 영양소 %DM) / 총 건물 kg
수분%          = 100 − (총 건물 kg / 총 원물 kg × 100)
Ca:P           = 총 Ca kg / 총 P kg
```

- `definitionID`가 없는 라인(예: 물)은 원물 총량에는 포함되고 영양소 합산에서는
  제외된다. 수분 계산 관점에서 물의 물리적 실제와 일치한다.
- 사용자 원료(USER_)는 카탈로그와 동일 경로(`IngredientProviding`)로 해석되며
  항상 카탈로그보다 우선한다.

## 2. 판정 (평가 엔진)

성장단계별 `StageCriteria`가 축마다 [부족 | 주의 | 적정 | 주의 | 과잉] 밴드를
정의한다. 축: CP, TDN, EE(상한형), NDF, ADF, Ca, P, Ca:P, 수분. 판정은 값과
밴드 비교만으로 결정되며 UI는 관여하지 않는다.

## 3. 목적함수

최적화는 `totalCoreGap`(가중 목표 이탈)을 1차 목적으로 최소화한다.

```
gap(m) = 2.5·dist(CP) + 2.5·dist(TDN) + 1.5·over(EE)
       + 1.0·dist(NDF) + 1.0·dist(ADF)
       + 1.2·dist(Ca) + 1.2·dist(P) + 2.0·dist(Ca:P) + 0.8·dist(수분)

dist(x)  = 적정 범위까지의 거리(범위 안이면 0)
over(x)  = 상한 초과분
```

여기에 제약 페널티를 더한 값을 탐색 점수로 사용한다:

```
score = gap
      + Σ 제약 위반 페널티   (원료별 min/max kg, 최대 조정 폭, 잠금 위반 — 하드 제약은 후보 생성 단계에서 차단)
      + w_cost · max(0, 비용 증가)    (선택, 기본 w_cost = 0)
```

변경량 억제는 별도 페널티 항 대신 **동률 시 타이브레이크**(액션 수 적은 순 →
|비용 변동| 작은 순)로 처리한다. 목표 이탈 해소가 항상 우선한다.

## 4. 제약 (SimulationConstraints)

| 제약 | 의미 | 처리 |
| --- | --- | --- |
| 잠금 원료 | 사용자가 고정한 원료는 증감 금지 | 조정 대상에서 제외 (하드) |
| 원료별 최소/최대 kg | 허용 투입 범위 | 후보 클램프 (하드) |
| 최대 조정 폭 | 원료당 ±비율 한도 (예: ±50%) | 후보 클램프 (하드) |
| 총량 | 최종안 총 원물 kg = 사용자 입력 총량 | 탐색 후 비례 정규화로 보장 |
| in-mix | 배합에 없는 원료 추가 금지 | 후보 생성 자체가 배합 내 원료로 한정 |
| 비용 가중 | 원료비 증가 억제 | w_cost > 0일 때 목적함수 가산 |

총량 정규화는 **엔진이 조정 가능한 원료에만** 동일 배율을 적용한다.
성분 미등록 라인(물 등)과 사용자가 잠근 원료는 절대 변경하지 않는다
(사용자 입력 무단 변경 금지 원칙 — 회귀 테스트로 고정).
고정 라인이 없으면 이 정규화는 %DM·수분%를 바꾸지 않는 순수 비례 스케일이 되고,
고정 라인이 있으면 정규화 후 지표를 다시 계산해 그 값으로 판정한다.

## 5. 탐색 방법

결정론적 다단 탐색. 난수는 고정 시드 xorshift64이므로 같은 입력 → 같은 출력.

1. **비율 최적화 (1순위)** — `optimizeInMixPlan`
   - 시작점 다변화: 현재 배합 / 균등 배분 / 조사료 중심 / 농후사료 중심
   - 좌표하강: 원료별 배율 {0, 0.2 … 3.0} 후보를 라운드 반복 적용
     (0 허용 = 원료 제외, 라운드 누적으로 대폭 이동 도달)
   - 전체 배율 이동: 조정 불가 라인(예: 물)이 있을 때 수분 축을 움직이기 위해
     조정 가능 원료 전체에 동일 배율 {0.25 … 3.0} 적용
   - 섭동 재시작 + 랜덤 워크 정련(고정 시드): 국소 최저점 탈출
2. **패턴 휴리스틱 (2순위, 폴백)** — 과잉/부족 패턴 분류 후 기여 상위 원료
   증감 + beam search. 최적화 실패 시 안전망으로 유지.
3. **검증** — 모든 후보는 `CalculationEngine.calculateMetrics` 재계산으로
   평가된다. 탐색기가 수치를 직접 만들지 않는다.
4. **정규화·산출** — 채택안을 원 총량으로 비례 정규화 후 원료별 증감 kg
   (원물 기준)으로 재산출.

## 6. 불능 케이스 처리

완전 적정(9축 전부 적정)에 도달하지 못하면:

- 결과를 조작하지 않고 `noSolution`을 반환한다.
- `limitationNotes`가 도달 불가 원인을 계산으로 판별해 문구화한다.
  예: 배합 내 최대 CP가 기준 하한 미만 → "단백질원 추가 검토",
  칼슘원 부재 + Ca:P 미달 → "석회석 같은 칼슘원 추가 검토".
- 가장 가까운 참고안(referenceOnly)을 함께 반환해 사용자가 방향을 볼 수 있게
  한다. 참고안 역시 총량 정규화를 거친다.

## 7. 재현성 전략

- 결정론: 난수 시드 고정, 부동소수점 연산 순서 고정(단일 스레드 @MainActor).
- `algorithmVersion`을 모든 저장 분석에 기록. 엔진 로직이 바뀌면 버전을 올리고
  CHANGELOG에 차이를 기록한다.
- 회귀 검증: 대표 배합 6종(경기TMR 3000kg, CP과잉, TDN과잉, CP부족,
  EE과잉+CP부족, 농가 배합)의 기대 결과를 XCTest 골든 케이스로 고정한다.

## 8. 알려진 한계

- 전역 최적을 수학적으로 보장하지 않는다(휴리스틱 전역화). 골든 케이스와
  민감도 테스트로 실용적 안정성을 확인한다.
- 원료 DB 일부(200번대 농사로 계열)의 미측정 값은 0으로 저장돼 있어 해당
  원료가 많이 들어간 배합은 섬유 축이 낮게 평가될 수 있다. 사용자 직접 입력
  값이 항상 우선한다. (docs/ingredient-fiber-estimates.md 참고)
