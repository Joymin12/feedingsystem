# 변경 이력 (CHANGELOG)

형식: [버전] - 날짜 — 요약. 엔진 동작이 바뀌면 algorithmVersion도 함께 올린다.

## [Unreleased] — 출시 준비 (2026-07-25 ~ )

### 아키텍처
- 단일 파일 프로토타입(3,237줄)을 MVVM + Engine + Repository 구조로 분리.
- CalculationEngine / CorrectionEngine을 순수 타입으로 추출
  (`IngredientProviding`만 의존, UI·저장소 비의존).
- UserDefaults 접근을 Repository 프로토콜 뒤로 은닉.

### 추천 엔진 (algorithmVersion 2.0.0)
- 정책 고정: 배합 내 원료만 사용, 신규 원료 추가 금지(부족 공급원은 문구 제안),
  최종안 총량 = 입력 총량(비례 정규화), 단일 대표안.
- 비율 최적화 탐색기 도입(좌표하강 + 전체 배율 이동 + 고정 시드 섭동/랜덤 워크).
  기존 패턴 휴리스틱은 폴백 유지.
  - 검증: 경기TMR 3000kg 배합이 noSolution → 완전 적정안 도출로 전환.
- 불능 케이스에 한계 요인 문구(limitationNotes) + 가장 가까운 참고안 반환.

### 데이터
- 원료 DB 출처 확정: 1~114 = 한국표준사료성분표(2022) (94/95 일치 검증),
  200~223 = 농사로 농식품부산물영양정보.
- 200번대 11종의 NDF/ADF를 표준사료성분표 공식값으로 보강, NFC 계산 산출.
  근거: docs/ingredient-fiber-estimates.md.

### 시뮬레이션·제약 (P2)
- SimulationConstraints 도입: 원료 잠금, 원료별 최소/최대 kg, 최대 조정 폭,
  비용 가중치. 제약 모드에서는 제약을 모르는 휴리스틱 폴백을 사용하지 않는다.
- Recommendation에 algorithmVersion 기록. 설명 엔진(RecommendationExplanationBuilder)
  분리 — 문제→조정→교차영향→한계→계산방식 5단 구조.

### 영속화 (P3)
- FormulaRepository / AnalysisHistoryRepository 추가. 배합은 수정 즉시 자동
  저장(초안 복구), 분석은 스냅샷(배합 사본+엔진 버전 포함)으로 저장/복제/삭제/복원.
- 손상 레코드는 요소 단위로 건너뛰고 로그를 남긴다(전체 손실 방지).

### 테스트 (P4)
- XCTest 타깃 신설: 계산·판정·최적화·영속화 22개 테스트 전부 통과.
- 테스트가 실제 버그를 검출: 총량 정규화가 잠근 원료·성분 미등록 라인(물)까지
  스케일하던 문제 → 고정 라인 불변 방식으로 수정(사용자 입력 무단 변경 금지).

### UI (P5)
- 추천안 화면을 "증감 → 적정 도달" 중심으로 확정: 원료별 +/− kg 조정안(총량
  유지 명시) + 적용 후 영양성분(축별 적정 배지) + 원료비 변화(현재→적용 후).
- 수동 시뮬레이션 워크스페이스는 제품 단순화 결정으로 제거(2026-07-26).
  추천안 = 증감 시뮬레이션의 출력이라는 단일 개념만 유지. 엔진의 제약
  기능(SimulationConstraints)은 남겨두었고 테스트로 커버된다.
- 분석 이력 화면: 저장 목록/스와이프 복제·삭제/스냅샷 상세/배합 복원.
- 설정·도움말: 성장단계 변경, 용어 사전, 데이터 관리, 엔진 정보·면책 고지.
- 접근성: 판정 배지에 아이콘+텍스트 병기(색상 단독 의존 제거).
- 배합 화면 실시간 총 원물량 표시 + 0kg 경고.
